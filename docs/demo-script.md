# 演示脚本（端到端）

前提：MySQL 运行、后端 8080、Worker 已启动、前端 dev server。
或者使用合成夹具 `python test-fixtures/scripts/generate_fixtures.py`。

## 场景 A：手动剪辑闭环（不依赖算法）

1. 打开前端 `/login`，注册并登录（如 demo1 / password123）。
2. `/upload`：拖入一段 10 秒合成视频。观察分片进度；中途刷新页面重新进入上传页
   再次选择同一文件——续传只补缺失分片。
3. 上传完成跳转 `/media/{id}`：等待探测完成显示时长/分辨率，预览可播放，缩略图生成。
4. `/media/{id}/timeline`：点击「添加手动事件」输入秒数创建标记；点击时间轴圆点跳转预览。
5. 「生成候选」或直接进入工程：`/projects/{id}` 添加两个片段
   （例如 1.0–3.5s 与 6.0–8.0s），第二段设置字幕「这波配合成功了」、音量 0.5，
   用数字输入微调边界，保存（生成版本 R1）。
6. 修改片段起点后再次保存 → R2。版本列表中 R1 仍可查看（不可变）。
7. 「保存并提交渲染」→ `/renders/{id}`：任务进度实时增长（解析 ffmpeg 真实进度），
   完成后页面内播放并下载 MP4。ffprobe 验证成片时长 ≈ 两段之和（帧级精度）。
8. 打开任务中心 `/tasks`：查看 ANALYZE/RENDER 等任务阶段、进度、尝试次数；
   对一个 QUEUED 任务点取消立即生效。

## 场景 B：自动定位（实验性，合成计数器视频）

1. 使用 `synthetic-counter-8s.mp4` 上传（画面中计数器每秒 +1）。
2. `/media/{id}`：选择「通用 OCR 区域识别（实验性）」适配器，
   注意实验性警示标签；ROI JSON 已预填（右上角计分区域，number 模式）。
3. 开始自动分析 → 任务中心看到 ANALYZE 进度 → 完成后进入事件时间轴：
   出现多条 SCORE_CHANGE 事件（来源 AUTO，带置信度与证据截图）。
4. 「生成候选」：默认规则（6s 窗口 ≥3 次事件）→ 候选列出且原因可读
   （"N 次 SCORE_CHANGE 事件出现在 6000 ms 窗口内…"）。
5. 「保留并建工程」：直接从候选创建剪辑工程并继续编辑渲染。

## 场景 C：安全与权限（口述或现场演示）

- 用第二个浏览器身份登录另一账号：无法通过 ID 访问他人素材/成片（404）。
- 成片分享：`POST /api/renders/{id}/shares` 得到一次性展示的令牌 URL，
  无痕窗口可下载该成片；撤销后同一 URL 返回 410；原始录像不可通过分享访问。
